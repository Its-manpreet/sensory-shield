You can start immediately: the settings UI can run as a plain HTML page with a mock store before Agent A's scaffold exists.

## Your job

### 1. Profiles and store (first, because everyone imports `src/shared/`)
- `src/shared/profiles.js`: the `Profile` schema from `docs/INTERFACES.md`, plus three default profiles with sensible numbers:
  - **photosensitive:** flash on and strict (low `maxFlashesPerSec` tolerance, red detection on), content detection off or light.
  - **graphic-sensitive:** flash on at default, content detection on with graphic categories, medium blur, labels on.
  - **custom:** everything editable, starts from graphic-sensitive.
- `src/shared/store.js`: `getSettings()`, `setSettings(patch)`, `onChange(cb)`. In the renderer it talks to the main process through `window.shield` (defined in Agent A's preload) using the IPC channels in `docs/INTERFACES.md`; for development use an in-memory mock. Stores settings only.
- Push this to `main` early (within the first hour) so A, B and C can import it.

### 2. Settings window (`src/settings/`)
A calm, accessible, simple window (the product is for people sensitive to visual stress, so the UI itself must be gentle):
- Big on/off switch. Profile picker.
- **Custom triggers:** a text box where the user types a trigger in plain words and adds it as a chip; chips can be removed. This is the wow moment in the demo, so it must be fast and obvious.
- Sliders: content sensitivity, blur strength, dim level, fade time. Toggle: show labels.
- "Always allow here" list placeholder (can be stretch).
- A small live status line: shield on/off, device used (WebGPU or CPU), checks per second (from `shield:stats`).
- **Accessibility of our own UI:** keyboard operable, visible focus, labeled controls, sufficient contrast, no animation that flashes, respects reduced motion. Test it with a screen reader if available (NVDA free on Windows, VoiceOver on Mac).

### 3. Demo assets (`assets/`) and calibration set
- Work with Agent B: flashing clips are generated by B's script into `assets/clips/` (small, short, names start `FLASH-WARNING-`). Also include `normal-video` examples (synthetic).
- Build the **calibration image set** for Agent C in `assets/images/`: a small, labeled set of **safe** images (documents, code editor, web pages, landscapes, people) plus agreed **mild stand-ins** for triggers (for example spiders for the custom-trigger demo; a generic "warning" style graphic). **Do not collect real gore, injury or violence.** Use images you generated or that are clearly free to use. Keep a `LABELS.md` listing each file and its expected result.
- Prepare a **demo page** (`assets/demo.html`) the team can open that contains: a safe article, a spot for the stand-in image, a button that plays a flashing clip. The demo must be repeatable and offline.

### 4. QA and demo support (from T+7:00)
- Run the **demo script** from the project doc end to end at least three times. Log every failure in `docs/STATUS.md`.
- **Record the backup video** of the whole demo working (after code freeze at T+10:30). This protects the team if something fails live.
- Prepare the **warning slide** that precedes any flashing content, and make sure test clips are small and short.
- Draft the slides with the team: hook, problem, why current tools fall short, our idea, how it works (two detectors), live demo, privacy, honest limits, team. Pull the real performance and accuracy numbers from `docs/STATUS.md` (flash check ms, model checks per second, false alarms and misses on the calibration set).

## Acceptance tests
- Changing a setting in the window changes behavior live, with no restart.
- A custom trigger typed in the window reaches the content detector (`setTriggers`) within a second.
- Settings persist across restart.
- The settings window is operable with only the keyboard.
- The demo page and all assets work with the network off.

## Do not
- Do not store anything except settings. Never frames or screenshots.
- Do not collect graphic, violent or copyrighted media.
- Do not change `docs/INTERFACES.md`; ask your human.
- Do not claim medical protection in UI text or slides ("reduces exposure to known triggers" is the wording).
