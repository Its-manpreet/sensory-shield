# Decisions and findings (append only, one short entry each)

- **2026-11-21 A: renderer modules, no bundler.** Renderers are plain `<script type="module">` over `file://` (works in Electron 45, verified by `npm run selftest`). Bare `@huggingface/transformers` resolves through an `<script type="importmap">` in each HTML page, pointing at `node_modules/@huggingface/transformers/dist/transformers.js` (the `.web.js` build has bare `onnxruntime-web/webgpu` imports that would need more map entries). Main process is Node ESM (`"type": "module"`); preload is `preload.cjs` because sandboxed preloads must be CommonJS.
- **2026-11-21 A: network is blocked at runtime.** `src/main/main.js` cancels every http(s)/ws request from renderers unless `SHIELD_ALLOW_NETWORK=1` (dev only, e.g. first model download). Agent C: Transformers.js/ORT fetch WASM files from a CDN by default, so point `env.backends.onnx.wasm.wasmPaths` at `../../node_modules/onnxruntime-web/dist/` and set `env.allowRemoteModels = false`, `env.localModelPath` to `models/`.
- **2026-11-21 A: install scripts.** npm 12 blocks dependency install scripts. `onnxruntime-node` and `protobufjs` are denied in `package.json` `allowScripts` (we use the web ONNX runtime, not the Node one). Electron's binary downloads normally.
- **2026-11-21 A: hotkeys.** Reveal 5 s: `Cmd/Ctrl+Alt+R`. Shield on/off: `Cmd/Ctrl+Alt+S`. Open settings: `Cmd/Ctrl+Alt+,`. Defined in `HOTKEYS` in `src/main/main.js`.
- **2026-11-21 A: Settings object** (not spelled out in INTERFACES.md): `{ enabled, activeProfileId, profiles: { [id]: Profile } }`, defaults in `src/shared/profiles.js` (`defaultSettings()`). Persisted to `<userData>/settings.json`. `settings:set` does a shallow merge of the top-level keys, so send the whole `profiles` object when editing a profile.
- **2026-11-21 B: flash detector follows WCAG 2.x, simplified.** Per 64x36 cell, linear-light relative luminance; a transition is a swing >= 0.1 with the darker side < 0.8; red transitions use (R-G-B)*320 changing by > 20 where R/(R+G+B) >= 0.8. A flash is a pair of opposing transitions; a cell is flashing at >= `maxFlashesPerSec` flashes in a 1 s sliding window. Simplifications: area is a share of the *screen* (`minAreaFraction` 0.25), not WCAG's 341x256 px at viewing distance, and we do not model viewing distance. Rects are the bounding box of flashing cells per region plus one cell of margin, so a flashing video in the middle does not dim the whole screen.
- **2026-11-21 B: defaults kept** (3 flashes/s, 0.25 area, 1500 ms hold). Tuned against synthetic normal video (moving gradients + hard cuts every 2.5 s), slow fade, 1 Hz and 2 Hz: no events. Protection tail after flashing ends is up to 1 s (flashes leave the window) plus `holdMs`: deliberately conservative.
- **2026-11-21 B: test clips** come from `npm run clips` (ffmpeg, `test/make-clips.sh`): 480x270, 4 s, VP9 webm, about 5 KB each, into git-ignored `assets/clips/`.
- **2026-11-21 A: macOS overlay placement.** A new frameless window is pushed below the menu bar (y=33 on a 14" MBP), which would offset every effect. Fixed with `enableLargerThanScreen: true` plus `setBounds(display.bounds)` after `setAlwaysOnTop(..., 'screen-saver')`. Verified: window 0,0 1470x956 = screen.
- **2026-11-21 A: macOS Screen Recording permission** belongs to the app that launched Electron (Terminal.app when run with `npm start`). Without it `desktopCapturer.getSources` fails with "Failed to get sources" and the app keeps running with no protection; main logs the permission status.
- **2026-11-21 A: blur rendering.** The region is drawn into a 1/12-size canvas, then scaled back up with a small `ctx.filter` blur and a faint dark veil. This is far cheaper than a large-radius blur at full resolution. Effects hold 800 ms after a region stops being reported, then fade out (fade time comes from the profile).
- **2026-11-21 A+D: glass fog is the default flash response.** The overlay keeps a 192x108 Float32 running average of the screen (time constant `smoothMs`, default 0.9 s), blurs it and draws it under a frosted, lightly tinted rounded panel with a hairline highlight and faint grain. A 6 Hz black/white flash becomes a steady grey; 3 Hz keeps about 7% of its swing before the extra `contrast(0.7)`. All flash regions merge into one panel (bounding box). Content tiles get separate frosted panes. Plain dim stays available.
- **2026-11-21 A+D: contract kept frozen.** Glass needed no contract change: flash regions are still `effect: 'dim'`, and the renderer draws them as glass or dim according to `settings.appearance = { flashStyle: 'glass'|'dim', smoothMs }` (Settings is not in the contract). PROPOSED additions for the humans to approve: channels `shield:status` (invoke -> `{screenAccess, platform, hotkeys}`), `shield:open-permission`, `shield:relaunch`; stats fields `device`, `capture`. They are already implemented and additive.
- **2026-11-21 A: overlay over full-screen apps (macOS).** The overlay is a `type: 'panel'` window at `screen-saver` level, visible on all workspaces including full-screen ones. Still to be verified live once Screen Recording is granted.
- **2026-11-21 B: scrolling is not flashing (fixes false alarms when scrolling e.g. Google Photos).** Per cell, scrolling a photo grid alternates bright/dark just like a flash. The detector now matches each 8x6-cell block against the previous frame shifted by up to ±8 rows / ±4 columns. A block is "moving" (its transitions are not counted, for 250 ms) when a shift leaves <= 60% of the unshifted difference AND the change is explainable by its own structure (change <= (shift+1) x 2 x mean spatial gradient). The second rule stops flat flashing areas from "matching" dark surroundings. Stable for gradient slack 1.25-3 and ratio 0.45-0.75 on all tests. Real-pipeline check (`test/browser/scroll-check.html`, Chromium downscale of a 2940x1912 photo page): old detector flagged 78-93% of scrolling frames, new 0%; flash detection times unchanged (3 Hz 1.0 s, 6 Hz 0.5 s, red 0.76 s). Known limits: a cell-sized checkerboard inverting in place can read as motion; a flashing ad inside a block that is scrolling at that moment is ignored until scrolling stops.
- **2026-11-21 A: sampler downscales in two steps** (screen -> 256x144 -> 64x36, high-quality smoothing) so cells are true area averages and do not shimmer.
- **2026-11-21 B: motion check made conservative after a miss report** ("doesn't blur actual flashing content"). A block is treated as moving only when (a) a shift explains the change, (b) the change is explainable by its structure, (c) the mean brightness did not change beyond the shift (residual < 0.06; real flashes change >= 0.1), and (d) two matches within 120 ms agree. When most of the screen is confirmed scrolling, the edge where new content enters counts as scrolling too (it cannot be matched). Search range ±14 rows. New must-detect tests: photo strobes (full screen and in a player), photo vs negative, strobe while panning, rapid bright/dark cuts.
- **2026-11-21 D: flash area thresholds lowered** to 0.10 (Photosensitive, close to WCAG's ~11% of a screen) and 0.15 (others); the old 0.25 missed a flashing YouTube player that is only partly flashing. Settings now carry `version`; `migrateSettings` takes new default numbers and keeps on/off, active profile, appearance and typed triggers. Real-pipeline scroll check with the 0.10 profile: max flagged area 0.8% (steady 1000-6000 px/s, flicks to 12000 px/s, jiggle).
- **2026-11-21 A: overlay re-fits its bounds** after load and on move/resize/display change. The macOS panel window was re-placed to y=-32 and 32 px taller, shifting every effect. Feedback-loop spike on macOS: PASS (`setContentProtection(true)` hides the overlay from capture).
- **2026-11-21 B: faster onset.** Besides "3 flashes in 1 s", a cell triggers after 4 transitions (2 flashes) spaced at >= 3 flashes/s (10% jitter allowed) IF the flash repeats: the two bright levels and the two dark levels left behind agree within 30% of the swing (scrolling past random content does not repeat). Real pipeline: 3 Hz 1001 -> 666 ms, 6 Hz 496 -> 329 ms, red 4 Hz 768 -> 501 ms (includes clip start-up). Scroll check unchanged (max 1.1% area).
- **2026-11-21 B+A: fast release when the content goes still** (paused video). A protected region with no visible change (>= 2 luma levels) releases after 2.5x its longest recent gap between changes, clamped to 150-400 ms, with the gap remembered for ~2 s. Even 6 Hz flash then pause: ~370 ms. A short-flash 3 Hz strobe (dark ~300 ms between flashes) and bursts with ~280 ms pauses stay protected (tests). While the video keeps playing, the normal holdMs still applies. Effects: hold 800 -> 100 ms, fade-in capped at 120 ms, fade-out = profile fadeMs (default 300 -> 250, settings v3). Overlay keeps the last regions up to 400 ms if the capturer delivers no frames. Demo clip paused: glass gone in 390 ms (was > 1 s; live app ~0.7 s).
- **2026-11-21 C: content detection uses LFM3-VL-2B (vision-language model) on a bundled llama.cpp server** instead of zero-shot CLIP (human request: any blocklist word, incl. broad ones like "gore", "pornography", "cartoon", "clowns"). Files: `LFM3-VL-2B-Q4_K_M.gguf` (1.1 GB, language model) + `mmproj-LFM3-VL-2B-Q8_0.gguf` (203 MB, vision encoder; the model GGUF alone has no vision tensors). Runtime: llama.cpp `b12359` `llama-server` (LFM3 needs >= b12088), spawned by main as a child process on 127.0.0.1, free port, **random per-launch API key** (llama-server allows all CORS origins by default, so a browser page could otherwise call it). Not Ollama: the app must package on its own. `npm run vision:setup` fetches the right llama.cpp build per platform (macOS arm64/x64, Windows Vulkan/CPU, Linux) and the model into git-ignored `vendor/` and `models/`.
- **2026-11-21 C: two-step check.** (1) detect: 896 px screenshot, "Find these things… JSON {label, bbox}" -> boxes in 0..1000. (2) classify: each box cropped at native resolution, "Which of these does this image show? number or 0". The 2B model often boxes the right thing with the wrong label or boxes harmless photos; on crops it is reliable. Parser tolerates `bbox_2d`, numbered/described labels and duplicate keys (seen). Eval on 8 composite screens (`test/vision/eval.js`, free Wikimedia images, not in git): 5/5 found (spider, cartoon, 3 clowns), 0 false alarms on 3 trigger-free screens, ~1.6 s per check on an M5 (Metal). Model loads in ~0.5 s warm / ~5 s cold. Not measured: real gore / pornography (we do not collect such media); the model is prompted with concrete descriptions for broad words. The model is loaded only when content protection is on and has a trigger (~1.3 GB RAM); checks run only when the screen changed, at most every 0.5 s, one at a time.
- **2026-11-21 A: packaging with electron-builder** (`npm run dist` / `dist:dir`): `vendor/llama.cpp/${platform}-${arch}` -> `resources/llama`, `models/lfm3-vl/*.gguf` -> `resources/models/lfm3-vl`; mac dmg, win NSIS, linux AppImage; unsigned. Verified on macOS arm64: packaged app spawns the bundled server on Metal (518 ms warm) and captures at 30 fps. Transformers.js / MobileCLIP removed (unused after the switch; it also dragged in onnxruntime-node). `productName` "Sensory Shield" moves the settings folder to `~/Library/Application Support/Sensory Shield`.
- **2026-11-21 A: content blur is much heavier than the flash glass** (extra 14-44 px blur by strength, +0.12-0.22 white tint): shapes under it are not recognisable; checked visually with `test/browser/content-blur-check.html`.
- **2026-11-21 C: pictures, not text; concepts; tighter boxes; faster.** Detect prompt now says "in the pictures/photos/drawings/videos… ignore written text… tight box"; crop check adds a direct "Is this image mostly text?" question (only for boxes that matched): it stopped headings like "Spiders: 10 facts about spiders" being blurred (they were accepted 3/3 runs before). New words get a model-written visual description once (text-only request, ~0.3 s, cached), e.g. "dead animals" -> "bones, skulls, remains, carcasses…"; built-in hints for guns, weapons, knives, gore, pornography… Labels are echoed short (descriptions on a "looks like" line) and detection runs at 640 px: the model's boxes are within ~0.2% of the true edges, so padding went 3% -> 0.8%. Temperature 0 (stable answers between checks). Eval on 7 rendered pages + 8 composite screens: 10/10 found, 0 false alarms (incl. text-only spider and gun pages), mean IoU 0.84, spill 11% (was 0.67 / 30%), ~1.2 s per check (was ~1.6 s). Parallel slots barely help on one GPU (1.20 -> 1.17 s); kept 2.
- **2026-11-21 A: blurs follow their content between checks** (`src/overlay/box-motion.js`): per frame, each box's row/column brightness profile (256x144 gray copy, memory only) is matched in the next frame; results that arrive after a scroll are moved by what their content did since the check started. End-to-end (real model, scripted scroll): coverage IoU while scrolling 0.39 -> 0.73, after a pause 0.00 -> 0.67, settled 0.75 -> 0.89.
- **2026-11-21 A: cursor and reveal.** The overlay never takes clicks (unchanged). New setting "Clear blurred pictures around the cursor" (`appearance.peekRadius`): main streams the cursor position (`shield:cursor`, proposed channel) and the effects cut a soft 110 px window through CONTENT blur only, never through flash protection. Reveal hotkey (⌥⌘R) now toggles: a second press ends the reveal; content labels show "· ⌘⌥R to show".
- **2026-11-21 (human 1): app is flash protection only for now.** Removed the vision engine (LFM3-VL / llama.cpp: `src/main/vision*.js`, `scripts/vision-setup.js`, `src/engine/content.js`, box tracking, cursor peek, tests and evals), the profile picker and the Content card from settings, and the packaging of llama.cpp + model. Kept: flash detector, glass/dim effects, settings (on/off, flash style, smoothing, dim level, red flashes, fade, labels), reveal hotkey, permission flow. Settings v4 migrates everyone to the Photosensitive profile (picker hidden). The full vision work is preserved at git tag `vision-v1` (and branch `c/content`) to redo later. Local `vendor/` and `models/` files are untouched and git-ignored.
- **2026-11-21 (human 1): pivot to a full sensory shield; each trigger has its own switch** (settings v7, `settings.sensory`, mix and match). Visual: flashing; red flashes; red/blue colour flicker (third tracker on linear r - b, swing 0.25, same flash rules; reported as kind 'red'; softened with desaturated glass); sudden brightness (`src/engine/brightness.js`: per 4x4 region, rise >= 0.25 linear and >= 3x within 250 ms from below 0.2 -> instant dark veil eased out over 1 s; suppressed where flash protection is active); constant motion (`src/engine/motion.js`, opt-in since videos are motion too: a 96x54 block keeps changing vs. 100 ms earlier in 80% of 3 s -> region shown at 2 fps, crossfaded). Real-pipeline gallery check (`assets/demo.html`): flash 0.31 s, red/blue 0.43 s, brightness at the jump, constant motion 3.0 s only when on; idle page and user scrolling: nothing.
- **2026-11-21 (human 1): bold-pattern and parallax detection removed** ("too useless"). Both worked in tests (patterns 5/5 + 0/13 false alarms on rendered pages; parallax 3/3 at 1.6-2.2 s) but are not worth their cost; code was never committed.
- **2026-11-21 A: flash detector ignores slow scrolling too.** Blocks no 1-frame shift explains are also matched against 3 frames back; white cards on a dark page at 200-450 px/s no longer read as flashing (test added).
- **2026-11-21 A+C: sound from what is playing.** System audio is captured with the screen (`audio: 'loopback'`; on macOS via Chromium features `MacLoopbackAudioForScreenShare,MacSckSystemAudioLoopbackOverride`, no install; capture is independent of the system volume, so no feedback). Chromium voice processing is turned off for true levels. `src/engine/loudness.js` decides a cut (dB <= 0) every 50 ms: sudden loud (>= 12 dB over the 3 s average, >= -32 dBFS) -> instant cut to ~4 dB over the average, 1.5 s release; leveling toward -22 dBFS (opt-in); sound after >= 4 s of silence starts 18 dB down and eases in over 2 s. Applied to the macOS system volume by a persistent JXA helper (~2 ms per change vs ~130 ms per osascript call); the user's own volume is the baseline and is restored when protection is off or the app quits. Live check: a loud sound after quiet ones was cut 9.5 dB on the first 50 ms reading, up to 19.5 dB at its peak. Windows: capture works natively but volume control is not implemented yet. Not done (too complex/unrealistic for now): trigger-sound classification (misophonia), noise suppression / voice focus, high-frequency EQ (needs a virtual audio device).
- **2026-11-21 (human 1): sudden-brightness easing and constant-motion calming removed** ("useless and buggy"): `src/engine/brightness.js`, `src/engine/motion.js`, their tests, the veil and frame-cap effects, the 96x54 motion sample, their settings switches and gallery panels. Settings v8 drops the keys. Remaining: flashing, red flashes, red/blue colour flicker, and sound (sudden loud, leveling, soft start). Earlier versions stay in git history (commit cc4432a).
- **2026-11-21 C+A: no audio hitch at sound start.** The soft start used to act after the sound was detected, so the first 10-50 ms played at full volume, then dipped 18 dB: worse than nothing. Now, after 5 s of silence the volume is lowered in advance (inaudible) and new sound starts quiet and eases in over 2 s; after the first sound the gain only rises (test). If the user changes the volume during a dip, that choice is respected until the dip ends (volume poll 1.5 s -> 0.5 s). Loudness is measured by an AudioWorklet every 10 ms (was a 50 ms timer). `SHIELD_NO_VOLUME=1` keeps tests away from the real system volume.
- **2026-11-21 B+A: faster visual protection.** Quick trigger: ONE full flash (swing >= 0.25 out and back to within 30% of the start, back within 190 ms) over the area threshold, in blocks with no sign of motion for 500 ms; the 2-flash and 3-in-1-s rules remain. Capture 30 -> 60 fps; slow-scroll check made time-based (~90-130 ms back) so it works at both rates; glass appears at full strength instantly (no fade-in) and is drawn in the capture callback that detected it. Real pipeline: 6 Hz 316 -> 153 ms, 3 Hz 655 -> 322 ms, red 4 Hz 488 -> 243 ms; normal video and all scroll checks (to 12000 px/s) still quiet; 2 Hz and single scene cuts still ignored. Floor: a single swing to bright is indistinguishable from a scene cut, so the earliest evidence is the swing back (half a flash period: 83 ms at 6 Hz, 167 ms at 3 Hz), plus ~1 capture frame.
- **2026-11-21 C+A: child safety, fast path (replaces the VLM idea for speed).** Target: blur within 100-200 ms. The LFM3-VL check took ~1.2 s, so pictures use small single-pass models instead: **MobileCLIP-S0** (Xenova/mobileclip_s0, fp16 WebGPU) scores 256 px screen tiles against trigger descriptions vs. ~55 ordinary-content descriptions (`src/engine/categories.js`, softmax x100, a trigger's probability summed over its prompts, threshold 0.45 at default sensitivity), and **NudeNet v3.4 320n** (YOLOv8n, **AGPL-3.0**: fine for the hackathon, check before shipping) boxes exposed body parts over the whole screen; it accepts 960x640 input (11-15 ms). Measured on M5 WebGPU: MobileCLIP ~5.7 ms per tile with no batching gain (16 tiles 91 ms); NudeNet 640m (65 ms) dropped for 320n at 640+.
- **2026-11-21 C: picture eval** (`test/content/image-eval.html`, 16 Wikimedia classes x 6 photos, each placed on a fake web page at web size and large): found 77/84 trigger screens (gun/rifle/knife/snake 12/12, spider 11/12, syringe 10/12, clown 8/12). False alarms on harmless look-alikes: 56 tiles over 108 screens, mostly steak tartare -> gore, kitchen knives / toy water guns -> weapons, classical nude statues -> nudity (arguably wanted in child-safety mode). Adding look-alikes as ordinary descriptions cut false tiles 82 -> 56 with no loss of hits. NudeNet fired on 9/192 harmless screens (4 of them nude statues). **Not measured: real nudity, real gore** (we do not collect such media); those rely on the models' published behaviour.
- **2026-11-21 C: explicit text in context, not keywords.** A single NSFW text classifier (DistilBERT, jdp8/distilbert-nsfw-text-classifier) caught 8/8 explicit lines but flagged 6/16 harmless ones ("Sex: Male/Female", "chicken breast", "sex education", "puberty"). Stage 2: lines it flags are re-read by an NLI model (**Xenova/DeBERTa-v3-base-mnli-fever-anli**) with the hypothesis "This text describes sexual activity or nudity in an erotic way." (3-way entailment >= 0.5). Picked among xsmall/small/base NLI models and 3 hypotheses on 24 sentences (24/24); then a **held-out set written afterwards: 23/24** (the miss: "Romeo and Juliet fall in love…" flagged 0.62). DeBERTa fp16 is 370 MB.
- **2026-11-21 C: text is judged as sentences, not glued lines.** Joining each OCR line with its neighbours made unrelated list items read as one sentence ("Chicken breast… Cucumbers… Strip the old paint…" -> 0.92). Paragraphs are split into sentences at . ! ?, at short lines (headings, form fields, list items) and before a line that starts like a new item. Context widens a blur, never creates one: a paragraph is blurred whole only if one sentence is explicit by itself AND the paragraph as a whole is. Rendered-screen check (`test/content/ocr-check.js`, 6 sections): both explicit sections blurred, all 4 harmless sections with trigger words readable.
- **2026-11-21 A: OCR = Apple Vision via a small Swift helper** (`src/main/ocr/shield-ocr.swift`, built by `npm run content:setup` into git-ignored `vendor/ocr/`). Grayscale pixels over a pipe, JSON lines back; memory only, the text is never logged. `.accurate` reads a 1470x956 screen in ~75 ms and correctly; `.fast` (18 ms) misreads e->8 and is unusable. Only the band of rows that changed is re-read (full width, so lines are never cut) and text-model scores are cached per sentence, so a typical re-check is 100-250 ms. macOS only: on other systems explicit-text protection reports unavailable and pictures still work.
- **2026-11-21 C+A: one GPU queue with priority** (`gpu()` in `src/engine/runtime.js`). ONNX Runtime Web cannot create two WebGPU sessions at once ("another WebGPU EP inference session is being created") and concurrent runs then crashed with "memory access out of bounds". Every load and inference now goes through one queue; pictures are high priority, text low, DeBERTa batches are 4 so a picture check waits at most ~25 ms.
- **2026-11-21 A: content blur drawing was slowing the models.** `paintGlass` filtered a full-screen (2940x1912) draw every frame and then clipped it; while a blur showed, MobileCLIP ran 3-7x slower. Now only the panel plus a blur margin is drawn. Live end-to-end (`npm run content:latency`: real app, a handgun photo shown 12x at random places on the real screen): median 191 -> **161 ms**, worst 499 -> **183 ms**, 12/12 blurred. Each picture check reads one CPU-side snapshot of the screen (logical resolution) instead of the GPU video per batch.
- **2026-11-21 A: content blurs do not depend on new frames.** The capturer may send no frames on a still screen; flash regions still expire after 400 ms without frames, but content blurs are refreshed on every display frame and end only when their area changes and is re-checked as safe.
- **2026-11-21 C+A: one pane per object, big first, then fitted, and it follows its content** (human 1: "a well placed box that moves is better than misplaced multiple ones"). Flagged tiles that touch become ONE pane at once; a detection that overlaps a pane (a fifth of either) joins it instead of stacking a second pane. On the next check the pane fits its picture: `findPictures` (src/engine/panes.js) finds dense blocks that stand out from the page background (judged on a ring wider than the pane, so a big photo is not taken for the page; text is too sparse to count), snaps them to the exact border, and MobileCLIP confirms which holds the trigger. No page background around (full-screen photo/video): the pane stays on the tiles. Panes grow at once and glide when they shrink (70 ms). Every frame each pane, and each explicit-text area, follows its pixels (box-motion.js from vision-v1 on the sampler's 256x144 gray); results computed on an older snapshot are moved by what the content did since. **Tried and dropped:** shrinking by cutting sides while the model still saw the trigger. MobileCLIP recognises a gun from a fragment, so panes shrank onto the barrel (live fit IoU 0.23).
- **2026-11-21 A: latency.** Tiles are scored most-changed first, the first batch is 2 tiles, the nudity detector runs after it, and a check stops early when something new appears in a tile that was still when it started (a playing video does not count). A pane with one miss is re-checked on every check so it cannot linger after its picture is gone. Live (`npm run content:latency`, test window pinned above other apps, 4 photos x 3, each shown 1.6 s then scrolled 260 px): first pane median **145 ms** (best 95 ms), one pane on 11/12, fit IoU median **0.84** (0.70 on a rifle product shot = the pane fits the rifle on its white background), **95%** of the photo covered while it scrolls. One spider photo was recognised only after 2 s (model miss, not placement). Runs where other windows came on top gave false panes: the live test needs the screen to itself for ~1 minute.
- **2026-11-22 C+A: fewer false blurs (window switches, trigger words in text, our own window).** (1) **Words are not pictures:** MobileCLIP reads text, so pages that only *name* a trigger ("Spiders: 10 facts", search results) were blurred: 92 flagged tiles on 14 text-only pages in `test/content/image-eval.html`. - **2026-11-22 C+A: written words are painted over before the picture model believes a hit** (human 1: "I don't want the word 'guns' or 'spider' to get covered"). The picture gate above still blurred words where there is no plain page around them (dark editors, chats: 32 kept tiles on 28 text pages).
